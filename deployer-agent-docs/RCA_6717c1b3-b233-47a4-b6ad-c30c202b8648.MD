# RCA — Techfest submission emails not delivered in production (oll.co)

## Problem
Admin reports Techfest emails from `/admin/competitions` are not delivered: confirmation (`POST /api/admin/techfest/submissions/send-emails` kind=confirmation), result (kind=result), and rework (`PATCH /api/admin/techfest/submissions/{id}/review`, `POST /api/admin/techfest/submissions/bulk-review`). All route through `_dispatch_email` in `backend/routes/techfest.py`.

## How `_dispatch_email` works (source, lines 32–78)
1. **Gmail SMTP first** — imports `GMAIL_APP_PASSWORD`/`GMAIL_EMAIL`; only attempts `smtplib.SMTP_SSL('smtp.gmail.com', 465)` **if `GMAIL_APP_PASSWORD` is truthy**. If empty, it skips straight to fallback with `gmail_err="GMAIL_APP_PASSWORD missing"`.
2. **Resend fallback** — sets `resend.api_key = os.environ["RESEND_API_KEY"]` and calls `resend.Emails.send(...)`. On any exception returns `{"provider":"none","success":False,...}`.
- From header for both paths: `Techfest Team <techfest@oll.co>`, Reply-To `techfest@oll.co`.
- Note: the dict is returned (not raised), so the endpoints respond **HTTP 200 with sent:0 / email_sent:false** and NO `"techfest ... email failed"` warning is logged — which matches what we see.

## Root cause — BOTH providers are broken in production
1. **Gmail path never runs.** `list_secrets` on the active run (`6717c1b3…`) shows `GMAIL_APP_PASSWORD` → `is_empty: true`. `GMAIL_EMAIL` is set. Because the password is empty, the code skips the SMTP block entirely → `gmail_err="GMAIL_APP_PASSWORD missing"`.
2. **Resend fallback fails with 401.** `RESEND_API_KEY` is present (non-empty) but **invalid**. Production backend logs (same `RESEND_API_KEY` env, used by `routes.inapp_notifications`) show, repeatedly:
```
2026-11-02 07:32:39,519 - routes.inapp_notifications - WARNING - [task-email] resend 401 to=founderoffice@oll.co body={"message":"API key is invalid","name":"validation_error","statusCode":401}
```
So `resend.Emails.send` raises → `_dispatch_email` returns `{"provider":"none","success":False}`.

Net effect: `_dispatch_email` returns provider="none", success=False. The `send-emails` / `review` endpoints return 200 (observed in logs: `POST /api/admin/techfest/submissions/send-emails 200 OK`, many `PATCH .../review 200 OK`) but with `sent:0` / `email_sent:false`, and **no email is actually delivered**.

## Why preview works but prod doesn't
In preview, `GMAIL_APP_PASSWORD` is also absent, so preview uses the Resend fallback — and preview has a **valid** `RESEND_API_KEY`. Production carried forward / holds a different `RESEND_API_KEY` value that Resend rejects as invalid (401). `RESEND_API_KEY` and `GMAIL_APP_PASSWORD` are user-owned secrets; the platform does not set them.

## Answers to the three questions
1. **Secrets in prod:** `GMAIL_EMAIL` = set/non-empty; `GMAIL_APP_PASSWORD` = **EMPTY**; `RESEND_API_KEY` = set/non-empty but **INVALID (401)**.
2. **Logs:** no `"techfest review/submission email failed"` lines (because `_dispatch_email` returns instead of raising), but the shared Resend key logs `resend 401 ... "API key is invalid"` — direct proof the Resend credential is bad in prod. No SMTP attempt is made (password empty).
3. **Endpoint responses:** HTTP 200, but internally `sent:0` / `email_sent:false` (success=False from `_dispatch_email`).

- **Provider actually used in prod:** none — Gmail skipped (no app password), Resend rejected (401).
- **Sender address recipients would see:** intended `Techfest Team <techfest@oll.co>` — but currently recipients see nothing because no mail is delivered.

## Fix (user action — Deployment Panel → Secrets, then redeploy)
Set at least ONE working provider, then redeploy:
- Set a valid **`RESEND_API_KEY`** (the same valid key used in preview, with the `oll.co` / `techfest@oll.co` domain verified in Resend), **and/or**
- Set a valid **`GMAIL_APP_PASSWORD`** (Gmail App Password for `GMAIL_EMAIL`) to enable the preferred Gmail SMTP path.

No code change is required — the dispatch logic is correct; it is failing purely on credentials.
